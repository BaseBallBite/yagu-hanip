# B1 8경기 검토 결과 — 기존 정규화 결과에 첨부

이 자료는 v1.1을 다시 실행하거나 원본을 변경하지 않는다. 검토 판단을 별도 파일로 연결한다.
전체 정규화 완료/공식 기록 대조 완료/주자 복원 완료를 뜻하지 않는다.

## 사용 방법
ZIP을 풀고 세 파일을 naver_relay_starter 폴더에 복사한다.
- b1_review_decisions.json
- verify_b1_review.py
- README_REVIEW.md

PowerShell에서 실행:
```powershell
py verify_b1_review.py --input .\data\b1_normalized_v11
```
8개 모두 MATCH, 마지막 REVIEW_FILE_MATCH이면 제공된 검토가 현재 데이터와 일치한다.
원본 문자·투구 객체 해시, 행 수, 참조 play_id, 안내 유형을 검사한다.
파일 쓰기·재수집·전체 시즌 재처리는 하지 않는다. 추가 대용량 출력은 없다.
MISMATCH가 있으면 그대로 공유하고 이 검토를 해당 데이터에 적용하지 않는다.

## JSON 해석과 소비자 처리
- source_action=KEEP_ALL: 원본과 plays를 삭제하지 않는다.
- order_action=PRESERVE_INPUT_ORDER: seqno로 재정렬하지 않는다.
- administrative_rows_not_for_play_accumulation: 구분선/승패투수 등 안내 행.
  UI에 안내로 표시할 수 있지만, 투구/타석/득점/아웃 상태 변경 이벤트로 누적하지 않는다.
- REPORTED_COLLISION_PATTERN_REVIEWED: 기재된 충돌 패턴을 검토했다. 판독·출루 원인·주자 복원 검토는 계속 남는다.
- HOLD_GAME_FOR_CANONICAL_TIMELINE: 이 경기 전체 plays를 정리된 타임라인인 것처럼 B2/AI에 자동 입력하지 않는다.
  원문 확인 및 입력 형식 개발은 가능하다. 실사용에는 반복 구간의 선택 근거가 추가로 필요하다.
- 이번 검토로 기존 review_flags/run_report를 지우거나 semantic_review_complete를 true로 바꾸지 않는다.
- 이 목록에 없는 경기도 검토 완료라고 가정하지 않는다.

## 남은 업무와 역할
B1: 3경기의 최종 타임라인을 확정할 근거 확인 또는 보류 사용 범위를 팀과 합의.
5/13은 누락된 교체가 포함된 후반 묶음이 보이지만, relay_no가 크다는 이유만으로 최종본이라고 확정하지 않았다.
5/26은 경기 목록/이닝별 공식 기록과 종료 시점을 추가 대조해야 한다.
6/12 SSG-삼성은 반복 타석의 실황 핵심 값과 통계 스냅샷을 구분하고 중복 선택 규칙을 확정해야 한다.
B1/B2: 출루 원인 미확정 1,737개, 비디오 판독 1,452개, 상황 안내 58개의 처리 책임과 범위를 합의.
B2: 직전/직후 상태와 주자 이동 복원. B1의 null을 0/false로 바꾸지 않는다.
B3: 검증된 상태/기록을 기반으로 사실 F 생성. 현재 자료는 완성된 F가 아니다.

## 전달
기존 b1_normalized_v11 결과와 이 검토 묶음을 함께 전달한다.
코드/명세/검토를 공유한 뒤 AI는 입출력 개발을 시작할 수 있다.
검토 파일의 보류와 원본 검토 항목을 무시하여 전체 시즌 정확성 검증 완료로 보고하지 않는다.
